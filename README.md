# SpeechAI

Приложение для анализа аудиозаписей стоматологических консультаций. Принимает запись длительностью до 120 минут, распознаёт речь через Yandex SpeechKit, оценивает разговор по шести этапам через YandexGPT и показывает диалог с таймкодами и отчёт.

## Что есть сейчас

- Загрузка аудио через сайт; список записей с фильтрами и карточка каждой консультации.
- Вход пользователей по паролю и вход врачей по ссылке из 1С.
- Три вида консультаций: первичная взрослая, первичная детская, повторная взрослая.
- Последовательная фоновая обработка через Celery и Redis. Этап и ID операции SpeechKit сохраняются для восстановления после перезапуска.
- Закрытый Yandex Object Storage для передачи длинного аудио в SpeechKit. Для запуска с настоящим Yandex его нужно настроить.
- Автоматические повторы временных ошибок. Подробности окончательной ошибки и ручной повтор доступны только администратору.
- Временная кнопка администратора для повторной обработки записей со статусом «ошибка» или «загружена»; готовые записи она не затрагивает.
- Подготовлена передача готовых записей на удалённый сервер. Она выключена до настройки WireGuard.
- Режим `MOCK_AI=true` для демонстрации без Yandex Cloud.

## Как пользоваться

1. Войдите в приложение и загрузите аудиозапись, указав дату, вид консультации, подразделение, врача и пациента.
2. Откройте запись из списка. Во время фоновой обработки статус обновляется в карточке.
3. После завершения просмотрите диалог и оценку. Врач видит свои записи, администратор — все.
4. В разделе «Пользователи» администратор управляет учётными записями и получает ссылки входа врачей.

## API и ссылки из 1С

- `GET /api/integration/1c` — получить нормализованные данные из параметров ссылки.
- `POST /api/integration/1c/normalize` — проверить и нормализовать JSON.
- `GET /api/integration/1c-link` — открыть форму с данными из 1С.
- `GET /api/integration/link-doctor?token=...` — войти как врач и открыть форму.

Ссылку входа врача создаёт администратор в разделе «Пользователи». Для передачи полей записи в ссылке используются параметры:

| Данные | Параметры |
| --- | --- |
| Консультация | `consultation_date`, `consultation_type`, `clinic_division` |
| Врач | `doctor_code`, `doctor_full_name`, `doctor_position`, `doctor_category` |
| Пациент | `patient_code`, `patient_full_name`, `patient_birth_date`, `patient_age`, `patient_gender`, `patient_phones`, `patient_emails` |

Даты — `дд/мм/гггг`; вид консультации — `primary_adult`, `primary_child` или `repeat_adult`. Код врача/пациента — до 9 символов; ФИО — до 70; должность — до 70; категория — до 35; возраст — до 2 цифр; пол — `М` или `Ж`. Телефонов и адресов почты может быть несколько. Обязательные поля записи: дата, вид консультации, подразделение, ФИО врача и ФИО пациента.

## Роли

- `doctor` — видит свои записи.
- `supervisor` — видит все записи.
- `admin` — видит все записи, управляет пользователями и сервисными действиями.

## Локальный запуск

Для запуска веб-приложения без Docker:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cd ..
cp .env.example .env
cd backend
uvicorn app.main:app --reload --port 8000
```

Для фоновой обработки дополнительно нужны Redis, Celery worker и Celery beat. Проще запустить полный набор через Docker Compose.

## Docker

```bash
cp .env.example .env
mkdir -p volumes/data
docker compose up -d --build
```

Сайт доступен на `http://127.0.0.1:8000`; на сервере внешний HTTPS принимает nginx. Docker Compose запускает веб-приложение, Redis, один worker и beat. При `MOCK_AI=false` для загрузки нужны ключи Yandex Cloud и закрытый бакет Object Storage.
